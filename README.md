# postscript_modoki

C 言語で書いた、PostScript 風のスタック指向言語のインタプリタです。

[karino2 氏の「暇つぶしプログラム教室 C言語編」](https://karino2.github.io/c-lesson/) に沿って、
標準ライブラリだけを使って一から実装しています。学習用のプロジェクトです。

```
$ echo "/double { 2 mul } def 5 double" > sample.ps
$ ./postscript_modoki sample.ps
result: 10
```

## ビルドと実行

`clang` または `gcc`（C11 対応）があればビルドできます。ほかに必要なライブラリはありません。

```bash
make              # unittest / postscript_modoki / trace をまとめてビルド
make test         # ユニットテストを実行
make test-asan    # AddressSanitizer を有効にしてテストを実行
make trace-run    # 代表的な例で内部動作のトレースを表示
make clean
```

```bash
./postscript_modoki <file.ps>   # ファイルを実行し、最後にスタックの一番上を表示
./trace "1 2 add"               # 任意のコードについて、内部の動きを表示
./trace -vm "1 2 add"           # 継続スタックのフレームと pc の動きを表示
```

## 言語の機能

### 値

```
42          整数
-5          負の整数
/x          リテラル名（実行せず、名前そのものを積む）
{ 2 mul }   実行可能配列（実行せず、コードのまとまりとして積む）
% コメント   % から行末までを読み飛ばす
```

### 演算子

| 分類 | 演算子 |
|---|---|
| 算術 | `add` `sub` `mul` `div` `mod` |
| 比較 | `eq` `ne` `lt` `gt` `le` `ge` |
| スタック操作 | `dup` `pop` `exch` `index` |
| 制御 | `if` `ifelse` `while` `repeat` `jmp` `jmp_not_if` |
| 定義 | `def` |
| ローカル変数 | `store_local` `load_local` |
| 出力 | `print` |

真偽値の専用の型はありません。整数で表し、`0` を偽、`0` 以外を真として扱います。

| 書き方 | 意味 |
|---|---|
| `n index` | 一番上から n 個下の値をコピーして積む（`0 index` は `dup` と同じ）。スタック上の位置で値を指すために使う |
| `n jmp` | `jmp` の次の要素から数えて、n 個先へ飛ぶ（負なら後ろへ戻る） |
| `条件 n jmp_not_if` | 条件が偽のときだけ、n 個先へ飛ぶ |
| `値 番号 store_local` | 実行中のフレームの `locals[番号]` に値を入れる |
| `番号 load_local` | `locals[番号]` の値を積む |

`jmp` と `jmp_not_if` は、実行中のフレームの `pc` を書き換える命令です。ローカル変数もフレームの中にあります。
そのため、この4つの命令は関数（`{ }`）の中でしか使えません。ローカル変数の番号は 0〜7 で、入れられるのは整数だけです。

`def` を含め、演算子はすべて辞書に登録されたプリミティブです。`eval` は演算子の名前を何も知りません。
名前が来たら辞書を引き、C の関数なら呼び出し、コードのまとまりなら実行し、それ以外の値なら積みます。

### 書き方の例

```
1 2 add                              → 3
10 3 sub                             → 7
/x 5 def  x x add                    → 10          変数
/double { 2 mul } def  5 double      → 10          関数
1 { 10 } { 20 } ifelse               → 10          条件分岐
-5 dup 0 lt { -1 mul } if            → 5           絶対値
5 { dup 0 gt } { 1 sub } while       → 0           ループ
3 { 10 } repeat                      → 10 10 10    回数を指定したループ
42 print                             → 42          出力
/f { 5 0 store_local 0 load_local 0 load_local add } def  f
                                     → 10          ローカル変数
```

関数の引数に名前を付けるときは、`/名前 exch def` という決まった書き方を使います。
`def` はスタックに「名前、値」の順で積まれていることを期待するので、`exch` で順番を入れ替えています。

```
/gcd {
  /b exch def        % 2 番目の引数を b にする
  /a exch def        % 1 番目の引数を a にする
  ...
} def
```

## サンプル

`sample/` に `.ps` ファイルのサンプルがあります。

```bash
$ ./postscript_modoki sample/fact.ps
result: 120
```

| ファイル | 内容 |
|---|---|
| `square.ps` | `dup mul` だけでできた、最小の関数定義 |
| `fact.ps` | 階乗の**再帰版**。`ifelse` と、関数が自分自身を呼ぶ再帰 |
| `fact_loop.ps` | 階乗の**ループ版**。`while` と `index` |
| `gcd.ps` | 最大公約数。`while` と、名前を付けた変数 |
| `fizzbuzz.ps` | FizzBuzz。`ifelse` を3段に入れ子にしたもの（文字列が無いので数値で代用） |
| `abs.ps` | 絶対値。`if` の代わりに `jmp_not_if` を直接書いたもの |
| `while.ps` | 0〜9 の合計。`while` とローカル変数 |
| `repeat.ps` | 2 の 5 乗。`repeat` とローカル変数 |
| `sample.ps` | `1 2 add 10 add` |

`fact.ps` と `fact_loop.ps` は、同じ階乗を別の書き方で実装したものです。

```
再帰版:   dup 1 sub fact mul            計算 3 つ、位置合わせ 0
ループ版: 1 sub exch 1 index mul exch    計算 2 つ、位置合わせ 3
```

ループ版に `exch` と `index` が必要なのは、スタック上の値に名前が無く、
「一番上から何番目か」という位置でしか指せないからです。
ローカル変数を使えば、このような位置合わせは不要になります（`while.ps` を参照）。

## 構成

```
        main.c / test_main.c / trace.c     ← main 関数を持つ 3 つの入口
                      │
                    eval ── cont  式の評価 / 継続スタック
                   ╱    ╲
          exec_array     dict     { } のコンパイル / 名前の辞書
              │           │
            parser      element   字句解析 / 値の表現
                          │
                        stack     値の置き場
```

| ファイル | 役割 |
|---|---|
| `parser.c/.h` | 文字列をトークンに分ける（`parse_int` / `parse_one`） |
| `element.c/.h` | スタックや辞書に入れる値の表現（タグ付き union） |
| `stack.c/.h` | オペランドスタック |
| `cont.c/.h` | 継続スタック。実行中の配列・次に実行する位置 `pc`・ローカル変数 `locals` を持つ |
| `dict.c/.h` | 名前から値を引く辞書（ハッシュテーブル + チェイン法） |
| `exec_array.c/.h` | `{ }` のコンパイルと保持（flexible array member）。`if` / `ifelse` / `while` / `repeat` の展開もここで行う |
| `eval.c/.h` | トークンの評価と、`eval_element_vm` / `run` による配列の実行 |
| `primitives.c/.h` | 組み込み演算子の実装と、辞書への登録 |
| `main.c` | `.ps` ファイルを実行するコマンド |
| `test_main.c` | ユニットテスト（`main` から 73 本を実行） |
| `trace.c` | 内部の動きを表示する学習用ツール |

`Stack` と `Dict` は、構造体の中身をヘッダで公開せず、`.c` ファイルの中に隠しています（不完全型とポインタ）。
そのおかげで、辞書を「配列と線形探索」からハッシュテーブルに作り替えたときも、使う側のコードは1行も変えずに済みました。

### 継続スタックによる実行

| 型 | 持っているもの |
|---|---|
| `Stack` | 計算に使う値。たとえば、階乗で後から掛ける整数 |
| `ContStack` | フレームの積み重ね。各フレームは、実行中の配列 `ea`、次に実行する要素の位置 `pc`、ローカル変数 `locals` を持つ |

`eval_element` は実行の入口です。継続スタックを作り、`eval_element_vm` で要素を1つ評価してから `run` を呼びます。
実行するものが無くなったら、継続スタックを解放します。

`run` は、一番上のフレームから要素を1つ取り出し、**評価する前に `pc` を1つ進めます**。
辞書に登録された実行可能配列を呼ぶときや、トップレベルに書いた `if` / `ifelse` を実行するときは、
新しいフレームを積むだけです。そのフレームを最後まで実行したら捨てて、呼び出し元の続きに戻ります。
実行可能配列がただの値として出てきた場合は、オペランドスタックに積みます。

たとえば `dup 1 sub fact mul` では、内側の `fact` を実行している間、呼び出し元の `pc` は `mul` を指したままです。
戻ってきたらそこから掛け算を続けるので、階乗の再帰は C の再帰呼び出しを使わずに動きます。

プリミティブの関数ポインタの型は `void (*PrimitiveFn)(Stack *, ContStack *, Dict *)` です。
`add` なども同じ引数を受け取り、使わない引数は `(void)cs;` のように明示しています。

`eval_exec_array` は、配列全体を1枚のフレームとして積んで `run` する関数です。
実行時の `prim_while` は、条件と本体をこの関数で実行します。そのため、`while` の中身は外側の継続スタックには乗らず、
入れ子になった別の `run` で動きます。ただし、`{ }` の中に書いた `while` はコンパイル時に展開するので（後述）、
`prim_while` が使われるのはトップレベルに書いた場合だけです。

### ジャンプ命令と if / ifelse の展開

`pc` を自前のデータとして持っているので、ジャンプは `pc` を書き換えるだけで実現できます。

`{ }` の中に `cond { A } if` があると、コンパイル時に次の形へ書き換えます。

```
cond  N jmp_not_if  A の中身...

N = A の要素数   偽のときは A を丸ごと飛ばす。else が無いので jmp は要らない
```

たとえば `1 { 10 20 } if` は、`1 2 jmp_not_if 10 20` になります。

`cond { A } { B } ifelse` は、次の形へ書き換えます。

```
cond  N1 jmp_not_if  A の中身...  N2 jmp  B の中身...

N1 = A の要素数 + 2   偽のときは「A の中身と N2 jmp」を飛び越えて B へ進む
N2 = B の要素数       真のときは A を実行した後、B を飛び越える
```

たとえば `1 { 10 } { 20 } ifelse` は、`1 3 jmp_not_if 10 1 jmp 20` になります。

展開した後は `if` や `ifelse` という命令が残らず、分岐のために新しいフレームを積むこともありません。
そのため、ブロックの中からも、関数のローカル変数がそのまま見えます。

`ifelse` を入れ子にした場合は、内側が先に展開され、その結果が外側にコピーされます。
ジャンプは相対的な距離で指定しているので、コピーしても飛び先はずれません。

直前の要素が `{ }` でない場合（コンパイル時に中身が分からない場合）は展開せず、
実行時の `prim_if` / `prim_ifelse` に任せます。トップレベルに直接書いた場合も同じです。

### ローカル変数と while の展開

`Continuation` に `int locals[LOCALS_MAX]`（8 個）を追加し、フレームごとの変数の置き場にしました。
関数を呼ぶとフレームが積まれ、戻るとフレームと一緒に locals も消えます。C のローカル変数と同じ寿命です。
呼び出された関数が同じ番号に書き込んでも、呼び出し元の値は壊れません。

ただし、ブロックが**別のフレーム**で実行されると、そのブロックからは関数の locals が見えません。
実行時の `prim_while` では条件と本体がそれぞれ新しいフレームで動くため、`while.ps` の結果は 45 ではなく 0 になっていました。
そこで `while` も `ifelse` と同じようにコンパイル時に展開し、関数と同じフレームの中に平らに並べています。

```
{ A } { B } while     A = 条件、B = 本体
  ↓
A の中身...  N1 jmp_not_if  B の中身...  N2 jmp

N1 = B の要素数 + 2           偽のときは「B の中身と N2 jmp」を飛び越えて、ループの外へ出る
N2 = -(A と B の要素数 + 4)   本体の後、展開した列の長さだけ戻って A の先頭へ行く
```

たとえば `{ C } { B } while` は、`C 3 jmp_not_if B -6 jmp` になります。
`ifelse` の N2 は前へ進む距離ですが、`while` の N2 は後ろへ戻る距離なので負の数になります。

### repeat の展開

`repeat` は、「回数を数えるカウンタを1つ加えた `while`」です。
本体がスタックに値を積んでもカウンタが影響を受けないように、カウンタはローカル変数の最後の箱（7 番）に置きます。

```
n { B } repeat
  ↓ 同じ意味
n 7 store_local                                         count = n
{ 7 load_local 0 gt }                                   while (count > 0)
{ B の中身...  7 load_local 1 sub 7 store_local } while   B; count = count - 1;
```

`exec_array.c` では、while の列を作る部分を `push_while(条件, 本体)` という関数に切り出し、
`expand_while` と `expand_repeat` の両方から使っています。
トップレベルに書いた `repeat` は展開されず、実行時の `prim_repeat` が C のループで本体を n 回実行します。

## テスト

```bash
make test        # 73 本のテスト関数を実行
make test-asan   # 同じテストを AddressSanitizer を有効にして実行
```

主なテストの内容は次のとおりです。

| 対象 | 確かめていること |
|---|---|
| 継続スタック | 基本的な操作、`run` による足し算、配列から別の配列を呼ぶこと、`ifelse` で分岐した後に呼び出し元の `3 add` へ戻ること。真偽の判定は `0` / `1` に加えて `2` / `-1` でも確認 |
| ジャンプ命令と `if` / `ifelse` | `jmp` / `jmp_not_if` それぞれの動き、`if` の展開結果（5 要素）と真偽それぞれの実行、`if` のブロックから関数のローカル変数が見えること、`ifelse` の展開結果（7 要素）、展開後の実行（真偽・複数要素の枝・入れ子）、直前が `{ }` でない場合は展開しないこと |
| ローカル変数 | 読み書きできること、番号ごとに別の箱であること、呼び出された関数が同じ番号に書き込んでも呼び出し元の値が残ること |
| `while` | 展開結果（6 要素）、展開後の実行（ローカル変数を使った 0〜9 の合計が 45 になること） |
| `repeat` | 展開結果（18 要素）、3 回・0 回の実行、本体から関数のローカル変数を使えること、トップレベルでの `prim_repeat` |
| 字句解析 | コメントの読み飛ばし、全角スペースを区切りとして扱うこと、ほかの全角文字が来たら読み取りを止めること |

期待値には、未実装の命令が読み飛ばされたときに偶然同じ結果にならない値を選んでいます。

`test-asan` を用意しているのは、`realloc` による配列の拡張を止めても、通常のテストが通ってしまったことがあるからです。
範囲外への書き込みは未定義動作なので、たまたま動いてしまうことがあります。
`malloc` / `realloc` のまわりを変更したときは、こちらも実行しています。

## トレース

内部で何が起きているかを表示するツール `trace` を同梱しています。モードは2つあります。

| モード | 表示するもの |
|---|---|
| `./trace "..."` | トークン、辞書の検索、値のスタック。配列の中身はトレース専用の実装で再帰的にたどる |
| `./trace -vm "..."` | `run` と同じループを1ステップずつ実行し、継続スタックの全フレームと `pc` を表示する |

通常モードは `pc` を持っていません。そのため、制御構文を展開した関数の本体のように `jmp` を含む配列は、
中身をまとめて実行し、`-vm` を使うよう案内します。

```bash
$ ./trace "/double { 2 mul } def 5 double"
```

```
[1] トークン: /double  (LITERAL_NAME)
    名前そのものを積む（実行しない）
    スタック: [ LITERAL_NAME "double" ]

[2] トークン: {  (OPEN_BRACE)
    compile_exec_array で } まで読み取る（実行はしない）
    できたもの: EXEC_ARRAY(count=2)
    items[0] = INT 2
    items[1] = EXEC_NAME "mul"
    それを1個の値として積む
    スタック: [ LITERAL_NAME "double" ][ EXEC_ARRAY(count=2) ]

[3] トークン: def  (EXEC_NAME)
  評価: EXEC_NAME "def"
    辞書を引く → PRIMITIVE <C関数>
    C関数なので呼ぶ
    スタック: [空]

...
```

`-vm` モードでは、関数を呼ぶとフレームが積まれ、最後まで実行すると捨てられて呼び出し元に戻る様子や、
`jmp` で `pc` が飛ぶ様子をそのまま見られます。
比較演算子を実行したときは、`-5 < 0 → 1（真）` のように、何と何を比べたかも表示します。
ファイルの中身をトレースするときは、`./trace -vm "$(cat sample/while.ps)"` のように文字列として渡します。

```bash
$ ./trace -vm "0 3 jmp_not_if 10 1 jmp 20"
```

```
(3) main の items[2] = EXEC_NAME "jmp_not_if"  （pc 2 → 3）
    継続: [main pc=6/7]          ← 偽なので 3 個飛んだ
    スタック: [空]

(4) main の items[6] = INT 20  （pc 6 → 7）
    継続: [main pc=7/7]
    スタック: [ INT 20 ]
```

## 既知の制限

### 値と入力

- 整数は `int` の範囲だけを扱います。`parse_int` が負でない数しか読まないため、`INT_MIN` は読めません。
- 文字列型と浮動小数点数はありません。FizzBuzz では、文字列の代わりに数値を出力しています。
- コメント以外では、ASCII 以外の文字（全角文字）を使えません。見つけた時点でエラーを表示し、読み取りを止めます。
  ただし全角スペースは打ち間違えやすいので、半角スペースと同じ区切りとして扱います。

### 変数

- `def` で定義した変数はグローバルです。再帰呼び出しから戻った後に読むと、内側の呼び出しで上書きされています。
  関数の中では `store_local` / `load_local` を使えば、この問題を避けられます。
- ローカル変数は整数 8 個までです。フレームを積んだときに初期化しないので、書き込む前に読むと不定の値になります。
- ローカル変数をトップレベル（フレームが無い場所）で使うと、`assert` で停止します。
- `repeat` はカウンタに 7 番の箱を使います。そのため `repeat` を入れ子にすると、内側と外側が同じ箱を共有して正しく動きません
  （`2 { 3 { 1 } repeat } repeat` は、1 を 6 個ではなく 3 個しか積みません）。本体の中で 7 番の箱を使っても壊れます。

### 制御とジャンプ

- トップレベルに書いた `if` / `ifelse` / `while` / `repeat` は展開されず、実行時にブロックごとのフレームで動きます。
  トップレベルにはローカル変数が無いので、実害はありません。
- `jmp` / `jmp_not_if` は、フレームのある `{ }` の中でしか使えません。トップレベルに書くと `assert` で停止します。
- 後ろに飛びすぎて `pc` が負になる場合のチェックはありません。

### メモリとエラー処理

- `exec_array_free` は、入れ子になった実行可能配列を解放しません。
- 継続スタックは 256 フレームで固定です。超えた場合は `assert` で検出します（通常のビルドの場合）。
- エラーは `stderr` への出力か `assert` による停止で扱っており、実行時エラーとして回復する仕組みはありません。
