# postscript_modoki

C言語で書いた、PostScript風スタック指向言語のインタプリタです。

[karino2氏の「暇つぶしプログラム教室 C言語編」](https://karino2.github.io/c-lesson/) に沿って、
外部ライブラリを使わず標準ライブラリだけで一から実装しています。学習用のプロジェクトです。

```
$ echo "/double { 2 mul } def 5 double" > sample.ps
$ ./postscript_modoki sample.ps
result: 10
```

## 現在の状況

第一部（全13章）のうち **13章の途中まで**（`repeat` が未実装）。
変数定義・関数定義・条件分岐・ループ・ローカル変数が動き、再帰も書けます。
階乗・最大公約数・FizzBuzz をこの言語で書いて動かせます。

- 11章: 実行可能配列を継続スタックと `run` のループで実行する（Cの再帰に頼らない）
- 12章: `jmp` / `jmp_not_if` を追加し、`{ }` の中の `ifelse` をコンパイル時に
  ジャンプ命令の列へ展開する
- 13章: フレームごとのローカル変数 `store_local` / `load_local` を追加し、
  `{ }` の中の `while` もジャンプ命令の列へ展開する

## ビルドと実行

```bash
make              # unittest / postscript_modoki / trace をビルド
make test         # ユニットテストを実行
make test-asan    # AddressSanitizer 付きでテストを実行
make trace-run    # 内部動作のトレースを表示
make clean
```

`clang` または `gcc`（C11対応）だけで動きます。依存ライブラリはありません。

```bash
./postscript_modoki <file.ps>        # ファイルを実行し、スタックのトップを表示
./trace "1 2 add"               # 任意のコードの内部動作を表示
./trace -vm "1 2 add"           # 継続スタックのフレームと pc の動きを表示
```

## 使える機能

### 値

```
42          整数
-5          負の整数
/x          リテラル名（実行されず、名前そのものが積まれる）
{ 2 mul }   実行可能配列（実行されず、コードの塊として積まれる）
% コメント   % から行末まで読み飛ばされる
```

### 演算子

| 分類 | 演算子 |
|---|---|
| 算術 | `add` `sub` `mul` `div` `mod` |
| 比較 | `eq` `ne` `lt` `gt` `le` `ge` |
| スタック操作 | `dup` `pop` `exch` `index` |
| 制御 | `if` `ifelse` `while` `jmp` `jmp_not_if` |
| 定義 | `def` |
| ローカル変数 | `store_local` `load_local` |
| 出力 | `print` |

真偽値は専用の型を持たず、`0` を偽、`0` 以外を真として整数で表します。

`n jmp` は、`jmp` の次から数えて n 個先へ飛びます（負の数なら戻る）。
`条件 n jmp_not_if` は、条件が偽のときだけ n 個飛びます。どちらも
実行中のフレームの `pc` を書き換える命令なので、`{ }` の中でしか使えません。

`n index` はてっぺんから n 個下の値をコピーして積みます（`0 index` は `dup` と同じ）。
スタック上の位置で値を指すための道具です。

`値 番号 store_local` は実行中のフレームの `locals[番号]` に値を入れ、
`番号 load_local` はそれを積みます。番号は 0〜7、値は整数のみです。
フレームの中にあるので、関数（`{ }`）の中でしか使えません。

`def` も含めて**すべて辞書に登録されたプリミティブ**です。`eval` は演算子名を
一切知らず、名前が来たら辞書を引いて、関数なら呼ぶ・コードの塊なら実行する・
値なら積む、を繰り返すだけです。

### 書ける例

```
1 2 add                              → 3
10 3 sub                             → 7
/x 5 def  x x add                    → 10     変数
/double { 2 mul } def  5 double      → 10     関数
1 { 10 } { 20 } ifelse               → 10     条件分岐
-5 dup 0 lt { -1 mul } if            → 5      絶対値
5 { dup 0 gt } { 1 sub } while       → 0      ループ
42 print                             → 42     出力
/f { 5 0 store_local 0 load_local 0 load_local add } def  f
                                     → 10     ローカル変数
```

変数に名前を付けるときは `/名前 exch def` を使います。
`def` は `[ 名前 ][ 値 ]` の順を期待するので `exch` で順序を合わせる、という定型句です。

```
/gcd {
  /b exch def        % 2番目の引数を b に
  /a exch def        % 1番目の引数を a に
  ...
} def
```

## サンプル

`sample/` に `.ps` のサンプルを置いています。

```bash
$ ./postscript_modoki sample/fact.ps
result: 120
```

| ファイル | 内容 |
|---|---|
| `square.ps` | `dup mul` だけの最小の関数定義 |
| `fact.ps` | 階乗の**再帰版**。`ifelse` と自己参照 |
| `fact_loop.ps` | 階乗の**ループ版**。`while` と `index` |
| `gcd.ps` | 最大公約数。`while` と名前付き変数 |
| `fizzbuzz.ps` | FizzBuzz。`ifelse` の3段の入れ子（文字列が無いので数値コードで代用） |
| `abs.ps` | 絶対値。`jmp_not_if` を手で書いた if |
| `while.ps` | 0〜9 の合計。`while` とローカル変数（C の while と1対1で対応） |
| `sample.ps` | `1 2 add 10 add` |

`fact.ps` と `fact_loop.ps` は同じ階乗を別の書き方で実装したものです。

```
再帰版:   dup 1 sub fact mul            計算3つ、位置合わせ0
ループ版: 1 sub exch 1 index mul exch    計算2つ、位置合わせ3
```

ループ版で `exch` と `index` が必要になるのは、スタックに変数名が無く、
値を「てっぺんから何番目」という位置でしか指せないためです。
ローカル変数を使うと、この曲芸が要らなくなります（`while.ps` を参照）。

## 構成

```
        main.c / test_main.c / trace.c     ← main を持つ3つの入口
                      │
                    eval ── cont  式の評価 / 継続スタック
                   ╱    ╲
          exec_array     dict     { } のコンパイル / 名前の辞書
              │           │
            parser      element   字句解析 / 値の表現
                          │
                        stack     値の置き場
```

| ファイル | 役割 |
|---|---|
| `parser.c/.h` | 文字列 → トークン列（`parse_int` / `parse_one`） |
| `element.c/.h` | スタックや辞書に入る値の表現（タグ付きunion） |
| `stack.c/.h` | オペランドスタック |
| `cont.c/.h` | 実行可能配列・次の実行位置 `pc`・ローカル変数 `locals` を保持する継続スタック |
| `dict.c/.h` | 名前 → 値の辞書（ハッシュテーブル + チェイン法） |
| `exec_array.c/.h` | `{ }` のコンパイルと保持（flexible array member）。`ifelse` / `while` の展開もここ |
| `eval.c/.h` | トークン列の評価、`eval_element_vm` と `run` による配列の実行 |
| `primitives.c/.h` | 組み込み演算子の実装と辞書への登録 |
| `main.c` | `.ps` ファイルを実行するコマンド |
| `test_main.c` | ユニットテスト（`main` から67本を実行） |
| `trace.c` | 内部動作を表示する学習用ツール |

`Stack` と `Dict` は構造体の中身をヘッダに公開せず、`.c` の中に隠しています
（不完全型 + ポインタ）。おかげで辞書を配列＋線形探索からハッシュテーブルへ
差し替えたとき、利用側は1行も変更せずに済みました。

### 継続スタックによる実行（11章）

| 型 | 保持するもの |
|---|---|
| `Stack` | 計算に使う値。例えば、階乗で後から掛ける整数 |
| `ContStack` | 実行中の配列 `ea` と、次に実行する要素の添字 `pc` |

`eval_element` は継続スタックを作り、`eval_element_vm` で要素を評価してから
`run` を呼び、実行予定がなくなったらスタックを解放する入口です。

`run` は最上段のフレームから要素を取り出し、**評価する前に `pc` を進めます**。
辞書に登録された実行可能配列の呼び出しや `if` / `ifelse` は、新しいフレームを
積むだけです。その配列を実行し終えたらフレームを捨て、呼び出し元の続きを実行します。
配列そのものが値として現れた場合は、従来どおりオペランドスタックに積みます。

例えば `dup 1 sub fact mul` では、内側の `fact` を実行している間、呼び出し元の
`pc` は `mul` を指しています。戻ってきたら掛け算を進めるので、この階乗の実行は
Cの再帰呼び出しに頼りません。

プリミティブの関数ポインタ型は `void (*PrimitiveFn)(Stack *, ContStack *, Dict *)`
です。`add` なども同じ引数を受け取りますが、使わない引数は `(void)cs;` などで明示します。

`eval_exec_array` は、配列全体を1枚のフレームとして積んで `run` する関数です。
実行時の `prim_while` は条件と本体をこの関数で実行するので、`while` の中身は外側の
継続スタックには乗らず、入れ子の `run` で動きます。13章で `{ }` の中の `while` は
展開されるようになったので、`prim_while` が使われるのはトップレベルに書いた場合だけです。

### ジャンプ命令と ifelse の展開（12章）

11章で `pc` を自前のデータにしたので、ジャンプは `pc` を書き換えるだけです。
`{ }` の中に `cond { A } { B } ifelse` があると、コンパイル時に次の形へ書き換えます。

```
cond  N1 jmp_not_if  A の中身...  N2 jmp  B の中身...

N1 = A の要素数 + 2   偽のとき「A の中身と N2 jmp」を飛び越えて B へ
N2 = B の要素数       真のとき A を実行したあと B を飛び越える
```

例えば `1 { 10 } { 20 } ifelse` は `1 3 jmp_not_if 10 1 jmp 20` になります。
実行時には `ifelse` という命令が存在せず、分岐で新しいフレームも積まれません。
入れ子の `ifelse` は内側から先に展開され、それが外側へコピーされます。
ジャンプが相対指定なので、コピーしても飛び先はずれません。

直前の2要素が `{ }` でない場合（コンパイル時に中身が分からない場合）は展開せず、
実行時の `prim_ifelse` に任せます。トップレベルに直接書いた `ifelse` も同様です。

### ローカル変数と while の展開（13章）

`Continuation` に `int locals[8]` を足し、フレームごとの変数置き場にしました。
関数を呼ぶとフレームが積まれ、戻るとフレームと一緒に locals も消えるので、
Cのローカル変数と同じ寿命になります。呼び出し先が同じ番号に書いても、
呼び出し元の値は壊れません。

ただし、ブロックが**別のフレーム**で実行されると、その中からは関数の locals が見えません。
動的な `prim_while` では条件と本体がそれぞれ新しいフレームで動くため、
`while.ps` は 45 ではなく 0 になっていました。そこで `while` も `ifelse` と同じく
コンパイル時に展開し、関数と同じフレームに平らに並べます。

```
{ A } { B } while     A = 条件、B = 本体
  ↓
A の中身...  N1 jmp_not_if  B の中身...  N2 jmp

N1 = B の要素数 + 2         偽のとき「B の中身と N2 jmp」を飛び越えてループの外へ
N2 = -(A + B の要素数 + 4)  本体のあと、展開した列の長さぶん戻って A の先頭へ
```

例えば `{ C } { B } while` は `C 3 jmp_not_if B -6 jmp` になります。
`ifelse` の N2 は前へ進む距離ですが、`while` の N2 は後ろへ戻るので負になります。

## テスト

```bash
make test        # 67本のテスト関数を実行
make test-asan   # 同じテストを AddressSanitizer 付きで
```

11章では継続スタックの基本操作、`run` による加算、配列から別の配列の呼び出し、
`ifelse` の分岐後に呼び出し元の `3 add` へ戻る動作をテストしています。
真偽判定は `0` / `1` に加えて `2` / `-1` も確認しています。
再帰版の階乗は `./postscript_modoki sample/fact.ps` で `result: 120` を確認しました。

12章では `jmp` / `jmp_not_if` の単体、`ifelse` の展開結果（7要素の並び）、
展開後の実行（真偽・複数要素の枝・入れ子）、`{ }` でない場合に展開しないことを
テストしています。

13章では、ローカル変数の読み書き・番号ごとに別の箱であること・呼び出し先が
同じ番号に書いても呼び出し元の値が残ること、`while` の展開結果（6要素の並び）、
展開後の実行（ローカル変数を使った 0〜9 の合計が 45）をテストしています。
期待値は、未実装の命令が読み飛ばされたときに偶然一致しない値を選んでいます。

`test-asan` を用意しているのは、`realloc` による配列の拡張を止めても
通常のテストが通ってしまった経験があるためです。領域外書き込みは未定義動作で、
たまたま動いてしまうことがあります。`malloc` / `realloc` まわりを触ったときは
こちらも実行しています。

## トレース

内部で何が起きているかを表示するツールを同梱しています。

2つのモードがあります。

| モード | 表示するもの |
|---|---|
| `./trace "..."` | トークン・辞書の検索・値のスタック。配列はトレース専用の実装で再帰的に辿る |
| `./trace -vm "..."` | `run` と同じループを1ステップずつ回し、継続スタックの全フレームと `pc` を表示 |

通常モードは `pc` を持たないので、`jmp` を含む配列（`ifelse` を展開した関数の
本体など）は中身をまとめて実行し、`-vm` を案内します。

```bash
$ ./trace "/double { 2 mul } def 5 double"
```

```
[1] トークン: /double  (LITERAL_NAME)
    名前そのものを積む（実行しない）
    スタック: [ LITERAL_NAME "double" ]

[2] トークン: {  (OPEN_BRACE)
    compile_exec_array で } まで読み取る（実行はしない）
    できたもの: EXEC_ARRAY(count=2)
    items[0] = INT 2
    items[1] = EXEC_NAME "mul"
    それを1個の値として積む
    スタック: [ LITERAL_NAME "double" ][ EXEC_ARRAY(count=2) ]

[3] トークン: def  (EXEC_NAME)
  評価: EXEC_NAME "def"
    辞書を引く → PRIMITIVE <C関数>
    C関数なので呼ぶ
    スタック: [空]

...
```

`-vm` モードでは、関数を呼ぶとフレームが積まれ、実行し終わると捨てられて
呼び出し元へ戻る様子や、`jmp` で `pc` が飛ぶ様子がそのまま見えます。
比較演算子を実行したときは `-5 < 0 → 1（真）` のように比べた中身も表示します。
ファイルをトレースするときは `./trace -vm "$(cat sample/while.ps)"` のように渡します。

```bash
$ ./trace -vm "0 3 jmp_not_if 10 1 jmp 20"
```

```
(3) main の items[2] = EXEC_NAME "jmp_not_if"  （pc 2 → 3）
    継続: [main pc=6/7]          ← 偽なので 3 個飛んだ
    スタック: [空]

(4) main の items[6] = INT 20  （pc 6 → 7）
    継続: [main pc=7/7]
    スタック: [ INT 20 ]
```

## 既知の制限

- 整数は `int` の範囲のみ。`INT_MIN` は読めない（`parse_int` が非負しか扱わないため）
- 文字列型・浮動小数点数は未対応。FizzBuzz は数値コードで代用している
- `def` の変数はグローバル。再帰呼び出しから戻った後に読むと、内側の呼び出しに
  上書きされている（関数の中では `store_local` / `load_local` を使えば避けられる）
- ローカル変数は整数8個まで。フレームを積んだときに初期化しないので、
  書く前に読むと不定の値になる
- 実行時にフレームを積む `if` のブロックと、トップレベルの `while` の条件・本体からは、
  外側の関数の locals が見えない
- ローカル変数はトップレベル（フレームが無い場所）で使うと `assert` で止まる
- `exec_array_free` は入れ子の実行可能配列を解放しない
- 継続スタックは256フレーム固定。容量超過は `assert` で検出する（通常のビルド時）
- `jmp` / `jmp_not_if` はフレームのある `{ }` の中専用。トップレベルに書くと `assert` で止まる
- 後ろへ飛びすぎて `pc` が負になる場合のチェックが無い
- エラーは `stderr` への出力か `assert` による停止で、実行時エラーとして扱う仕組みはない
